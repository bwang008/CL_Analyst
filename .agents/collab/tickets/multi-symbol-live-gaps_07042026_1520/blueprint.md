# Gap Analysis Blueprint — multi-symbol-live-gaps_07042026_1520
**Ticket Directory:** `.agents/collab/tickets/multi-symbol-live-gaps_07042026_1520/`
**Scope:** Everything required for a non-CL strategy config (reference: `configs/strategies/ES01B_Sharpe_E03_07042026.json`) to run correctly as a single `python -m src.live_execution.cli --config <json>` instance. The fleet runner (`.agents/collab/tickets/multi-config-fleet-runner_07042026_0646/blueprint.md`) needs no changes; every gap below is inside the per-instance path or the config generator.
**Analysis date:** 2026-07-04 (branch `development`). Read-only review — no source modified.

---

## Gap Summary

The live engine is CL-shaped at every layer below the `symbol` string. Even though `execution_symbol` is threaded through ~50 call sites in `live_trader.py`, the leaf implementations ignore or override it: every historical/continuous data request is built by `build_cl_contract()` regardless of symbol, every contract carries `exchange="NYMEX"`, marketable-limit and TP/SL prices are computed with a hardcoded `0.01` tick and `round(…, 2)`, all warm-start/cache/master-ledger/roll-metadata paths are CL files shared across instances, and the macro/COT feature engine instantiates with the CL instrument default (crude-oil COT + OVX staleness rules would silently feed an ES model). On top of that, the config generator (`agent/generate_ensemble_artifacts.py`) deep-copies a CL base config — which is why the ES config says `"execution_symbol": "CL"` — and derives an `E2E_ES_HourSet_01B_*` experiment prefix that does not match the `E2E_HourSet_01B_*` artifacts the sweep actually produced (they DO exist locally; the config paths are wrong). Grains additionally break the CL-tuned market-hours model (watchdog reconnect storms during daily halts) and the 4320-bar 1h warmup validation (280 calendar-day seed lookback yields too few bars). The training side already has the correct abstraction — `src/core/instrument_master.py` (tick size/value, CFTC code, FRED vol series) and an instrument-parameterized `MacroFeatureEngine` — but the live path never passes an instrument, and the registry itself is missing the live-only fields (IB exchange, multiplier, roll cycle, trading hours, live vol index symbol).

**Totals: 8 BLOCKER, 7 MAJOR, 5 MINOR.**

## Recommended Architecture

**One `symbol`, declared once, validated hard, resolved to an `Instrument`, injected everywhere.**

1. **Config is the source of truth.** `execution_symbol` in the strategy JSON is required — remove the `"CL"` default at `live_trader.py:276-278` and RAISE (`KeyError`/`ValueError`) when absent, per the no-silent-null-defaults rule. Optional `brain_symbol` (defaults to execution_symbol; preserves the CL-brain/MCL-hands pattern via `micro_of` metadata instead of special-casing MCL).
2. **Validate at startup:** `symbol` must (a) exist in `INSTRUMENT_REGISTRY` (`get_instrument` already raises), and (b) match the model: parse the dataset/symbol tag out of `models.*.experiment_id` or require a new `symbol` field the generator writes; mismatch → RAISE before connecting to IBKR. This is the cheap insurance against exactly the bug the ES config shipped with.
3. **Extend `src/core/instrument_master.py`** (M7) with live fields: `exchange`, `multiplier`, `active_months` (e.g. ES `"HMUZ"`, ZC `"HKNUZ"`, GC `"GJMQVZ"`, CL all 12), `roll_buffer_days` (FND-aware for physically delivered), `session_hours` (or `use_ib_trading_hours: bool`), `bars_per_day_5m`/`bars_per_day_1h`, `live_vol_index` (IB index symbol, e.g. `"GVZ"`), `micro_of`. **Every accessor raises on missing metadata — no `.get(..., default)`.** Live code imports this registry; nothing else invents symbol facts.
4. **DataFeed/ExecutionClient take the instrument at construction.** `DataFeedFactory.create(..., instrument=…)` / `ExecutionFactory.create(..., instrument=…)`. Inside `ibkr_client.py`, replace `build_cl_contract`/`build_mcl_contract` with one `build_future_contract(symbol, exchange, *, continuous, contract_month)`; `fetch_historical_bars*` and `get_front_month_contract` take `symbol`+`exchange` (or read the adapter's instrument); `close_*_position` re-qualifies from the cached contract instead of injecting `"NYMEX"`. Keep the old function names as thin CL-bound wrappers only if existing tests demand them.
5. **DataManager takes the instrument** and derives all paths: `seed_path` default `raw/{sym}-5m_bk.csv` / `processed/{SYM}_raw_1h.parquet`, `cache` `processed/warm_start_cache_{SYM}[_1h].parquet`, ledger `processed/{sym}_continuous_master[_1h].parquet`, roll metadata `processed/.roll_metadata_{SYM}.json`. CL keeps its legacy filenames via an explicit mapping in the instrument metadata (`legacy_paths`) so nothing moves for the running CL fleet. Seed missing → existing hard RAISE (keep verbatim). `live_config` gains optional overrides `seed_path_5m`, `cache_path`, mirroring the existing `seed_path_1h`.
6. **Pricing goes through one helper:** `round_to_tick(price, tick)` + `marketable_buffer = 2 * tick` used by `place_bracket_order`, `place_entry_order`, `place_child_orders`, `close_*_position`, and live_trader's TP/SL/trailing computations (`live_trader.py:1070,1632-1656`). Tick from instrument; no float literal anywhere.
7. **Features:** `build_live_features(..., instrument=…)` and `MacroFeatureEngine(instrument=…)` at all four live_trader call sites; `_needs_macro`/`_has_external_macro` become `startswith(("MACRO_", "COT_"))`. Daily-close overrides fetch `{"VIX"} ∪ {instrument.live_vol_index}`.
8. **Hours/watchdog/rollover:** `_get_market_status` consults the instrument session map (simplest robust source: cache IBKR `contractDetails.tradingHours` at qualification and evaluate against it); `get_front_month_contract` filters `active_months` and uses `roll_buffer_days`.
9. **CLI:** `--seed-path`/`--cache-path` defaults become `None` → resolved per-symbol after the config is loaded (currently `cli.py:167-172` bakes CL paths in before the config is even read).

This keeps the fleet-runner contract intact: still one process per JSON, still `live_config.client_id` isolation; the only new requirement is that each JSON carries a truthful `execution_symbol`.

## Config Generator Fix

`agent/generate_ensemble_artifacts.py` (and the same pattern in `agent/batch_post_optimizer.py:1045-1074`):

1. **`execution_symbol` provenance:** it comes from the deep-copied base config (`defaults.strategy_config` → `configs/strategies/hourly_ensemble_010.json`, a CL strategy) and is never touched (`:354-357`). Fix: after the deep copy, `cfg["execution_symbol"] = manifest["baseline"]["symbol"]` — and RAISE if `baseline.symbol` is missing (it is present in all v2 manifests, `batch_manifest_v2_es_hourset01b_scout.json:12`). Do the same in `batch_post_optimizer.py`'s optimized-config emission.
2. **E2E prefix mismatch:** `:324-327` derives `e2e_dataset_tag` with `re.search(r'bk_(.+)$', data_basename)` and falls back to the full basename → for `ES_HourSet_01B.parquet` it yields `E2E_ES_HourSet_01B`. But `gcp/vm_e2e_pipeline.py:653-663` strips the leading `{symbol}_` → real registry dirs are `E2E_HourSet_01B_*` (confirmed on disk in `reports/sweep_es01b_2x1_6h_scout_20260704-0701/registry/production_output/registry/`). Fix: extract the tag-derivation into one shared function (strip `bk_` OR `{symbol}_` prefix, exactly as vm_e2e_pipeline does) and use it in the generator. Add a generation-time existence check: if `model_path` doesn't exist in the local `reports/` tree, print a loud warning (paths may legitimately be cloud-only, so warn not raise — but the *name derivation* must match).
3. Optionally emit `live_config.seed_path_1h` (e.g. `processed/ES_raw_1h.parquet`) so the config is self-sufficient once T2 lands.
